# Ergalics Studio

Ergalics Studio 是一个完全运行在浏览器中的科学计算工作站，在同一工作区内完成数据导入、可视化、统计检验、数值仿真与报告生成的完整分析流程。项目与数据保存在本机存储，分析全程不依赖服务器；源代码与测试体系以 MIT 协议公开。

## 一、概述与定位

科学计算的实际工作常被三类成本拖慢：

- **环境成本。** 桌面软件需要安装、配置与许可，在公共机房或借用的电脑上往往无法快速重建自己的工作环境。
- **数据成本。** 云端平台免安装，但数据要上传到服务方，涉及未发表数据或受限样本时这一步直接不可行。
- **交付成本。** 分析做完只是开始，图要排成期刊格式、结论要写进报告，数月后需要重跑时，当初的参数与数据版本未必还在。

Ergalics Studio 把分析全程放进一个网页标签页，对上述三类成本的回答构成三个基本事实：运行环境只是一个网页标签页，`npm run dev` 或 GitHub Pages 皆可启动；数据全程留在浏览器本地存储（IndexedDB / OPFS），无账号、无上传；每一次分析自动记录参数、种子、代码与数据指纹，复现状态可以被显式检查。

| 维度 | 桌面科学软件（典型形态） | 云端计算平台（典型形态） | Ergalics Studio |
| --- | --- | --- | --- |
| 启动方式 | 安装并配置环境 | 打开网页，需注册 | 打开网页即用，无需注册 |
| 数据位置 | 本机 | 上传至服务方 | 始终在本机，可导出 `.clproj` 流转 |
| 离线可用 | 可用 | 通常不可用 | 全功能离线可用 |
| 计算内核 | 完整 | 由平台限定 | 14 个 WGSL 内核 + CPython / webR / DuckDB，均配一致回退 |
| 结果复现 | 取决于个人工作流 | 取决于平台快照 | repro.lock 五类指纹，漂移可判定 |
| 扩展方式 | 插件 / 脚本，门槛不一 | 平台限定 | `.cspkg` 与内置插件同契约、同沙箱 |

表中"典型形态"列描述各类方案的常见特征，非针对特定产品。

产品由四部分构成。其一是四模式工作台，从拖入数据查看结果，到流程管线、积木编程与真实脚本，共享同一份中间表示；其二是 107 个内置插件，覆盖 16 个学科的可视化、仿真与数据分析；其三是 26 个科研工具，承接画像、清洗、推断、组图、报告与复现各环节；其四是浏览器内运行时，包括 CPython（Pyodide）、webR、DuckDB-WASM 与 14 个 WGSL 计算内核。项目同时是一个 Git 仓库，版本历史与分析过程留在本机。

下表汇总本书引用的核心数字，各项均可在公开仓库中核查：

| 维度 | 现状 |
| --- | --- |
| 内置插件 | 107 个，覆盖 16 个学科（97 个随启动自动加载，10 个按需加载） |
| 科研工具 | 26 个，分六组，均可嵌入工作台画布 |
| 流程区块 | 38 个，覆盖数据源、变换、过滤、数学、统计、单位、可视化与绘图 |
| 计算内核 | 14 个 WGSL 计算内核，各配数学一致的 CPU 实现 |
| 脚本运行时 | CPython（Pyodide）、webR 0.6.0、DuckDB-WASM，随应用自托管 |
| 数据格式 | CSV / JSON / HDF5 / NetCDF / FITS / Zarr / Parquet 等统一导入 |
| 质量保障 | 2815 个单元测试（173 个文件）、14 套端到端测试、5 条 CI 工作流 |
| 开源治理 | MIT 协议；发版经 Zenodo 归档并铸造 DOI；SBOM 与引用元数据齐备 |

上述数字背后是三条已经成立的技术前提。

**其一**，浏览器图形与计算接口成熟：WebGPU 在主流浏览器默认启用，WebAssembly 以接近原生的速度运行 CPython 与 R 解释器，这使"在网页里做严肃计算"从权宜方案变为工程可行。

**其二**，本地存储能力足够：Origin Private File System 与 IndexedDB 提供 GB 级持久化，数据集、运行记录与 Git 历史都存放在其中，关闭浏览器后依然保留。

**其三**，开放格式保证可迁移：项目可随时导出为单个 `.clproj` 文件在设备间流转，数据文件本身不被包装进私有格式。

不同使用者在其中找到各自的入口：第一次接触数据的人从标准模式拖入文件开始看图；需要整理多步流程的分析者用流程模式搭管线并逐步预览；教编程的课堂从积木模式进入，再平滑过渡到真实脚本；熟悉 Python 或 R 的研究者直接在代码模式里调用 `studio` 接口操作项目数据。四种入口共享同一份数据与运行记录，起点不同，终点一致。

## 二、典型运行实例

以下实例分别对应六类典型计算：GPU 渲染、蒙特卡洛模拟、偏微分方程数值解、复分析可视化、格子玻尔兹曼流体与参数化研究。画面均来自当前构建的内置插件与科研工具，加载示例数据或调整参数后即可重现；本节只描述各实例的计算内容，完整清单见第三章与第六章。

**黑洞光线追踪**：特效插件对视场内每条光线做 Schwarzschild 时空的测地线积分，光线在引力场中弯曲后采样吸积盘辐射；吸积盘的亮度与色移计入相对论性多普勒集束和引力红移，观察者倾角、盘半径与分辨率以滑块调节，渲染由 WebGPU 逐帧完成。

![黑洞 · 3D 光线追踪：Schwarzschild 测地线与吸积盘](../assets/screenshots/plugins/fx-blackhole.png)

*黑洞 · 3D 光线追踪：逐像素测地线积分渲染的引力透镜与吸积盘。*

实例的数值口径可以与理论直接对照：伊辛插件在周期方格子上运行 Metropolis 与 Wolff 单团簇算法，观测磁化率、比热与 Binder 累积量，χ(T) 峰位拟合给出 Onsager 临界温度；黑洞渲染对每条光线做 RK4 测地线积分，多普勒集束吸积盘、引力红移与引力透镜星空随观察者参数实时更新。峰位与理论值一旦出现系统偏离，即可作为模型或参数问题的线索回查。

**统计物理**：二维伊辛插件在周期边界格点上运行 Metropolis 与 Wolff 团簇翻转两种蒙特卡洛算法；温度滑块扫过临界区域时，可以观察自发磁化的形成与消失。插件同时输出比热、磁化率与关联长度曲线，用于定位相变温度并检查有限尺寸效应，每次运行使用可复现的随机种子。

![二维伊辛模型：蒙特卡洛构型与磁化率](../assets/screenshots/plugins/physics-ising.png)

*二维伊辛模型：Metropolis / Wolff 蒙特卡洛的磁化构型与磁化率诊断。*

**偏微分方程数值解**：Gray-Scott 反应扩散插件以显式 FTCS 格式求解两种物质浓度的反应扩散方程，二维浓度场随时间演化出斑点、条纹与迷宫等图样；进料率与消去率两个参数决定图样类型，内置预设按 Pearson (1993) 的分类命名，也可从预设出发微调观察图样之间的转换过程。演化在 N×N 周期网格上进行，内置质量守恒数值基准用于核对求解器。

![Gray-Scott 反应扩散：图灵斑图](../assets/screenshots/plugins/chem-turing.png)

*Gray-Scott 反应扩散：FTCS 数值解形成的图灵斑图，按 Pearson 分类标注。*

**复分析可视化**：域着色插件对复函数 f(z) 逐像素计算幅角与模，分别映射为色相与亮度；内置表达式解析器，支持缩放与平移，等值线带按对数模长绘制，绕数按辐角原理统计，零点与极点的位置在色彩变化中直接可读，是复变函数教学与函数探索的直观工具。

![复变函数域着色：幅角与模长的色彩映射](../assets/screenshots/plugins/math-domaincolor.png)

*复变函数域着色：色相编码幅角、亮度编码模长，零点与极点清晰可辨。*

**流体模拟**：格子 Boltzmann 插件以 D2Q9 格子模拟二维通道流，圆柱绕流的涡街随时间步推进逐步显现；计算由 GPU 内核逐步执行，并在设备不支持时降级到 CPU 完成。

![格子 Boltzmann 流体：D2Q9 通道流与涡街](../assets/screenshots/plugins/lbm-fluid.png)

*流体模拟：D2Q9 格子 Boltzmann 通道流，GPU 逐步计算并支持 CPU 降级。*

**参数化研究**：参数扫描工具对指定参数网格逐一运行模型并汇总输出指标，结果以热力图与曲线呈现，用于观察模型行为对参数的敏感性、定位稳定区间，也为后续的不确定性分析圈定输入范围。扫描计划被展开为确定性设计点：全网格与列表轴取完整笛卡尔积，拉丁超立方轴按维度分层抽样，混合两种抽样的方案被显式拒绝——此时样本量没有无歧义的定义；执行完成后可查看响应面。

![参数扫描：参数网格与指标热力图](../assets/screenshots/platform/laboratory/parameter-sweeps.png)

*参数扫描：参数网格上的指标热力图与响应曲线。*

六个实例共享同一组运行条件：全部计算发生在浏览器标签页内，不依赖任何服务器；参数与随机种子可复现，同一组输入必然得到同一组输出；关键指标经统一的科学输出总线汇入画布顶部的读数条，与图、表一起进入后续的报告与复现记录。

驱动这六个实例不需要编写代码：滑杆、下拉与文件控件即可完成全部操作。需要更细的控制时，切换到代码模式，同一份数据与参数在脚本中继续可用——六种实例的计算路径都同时暴露给插件面板与脚本接口。

## 三、产品构成与工作模式

产品的核心是一条完整链路：数据进入、探索、建模推断、出版级组图、报告交付、全程可复现。每一段由对应的科研工具承接，且整条链在浏览器内闭合。

```mermaid
flowchart LR
  A[数据导入] --> B[画像与清洗]
  B --> C[建模与推断]
  C --> D[Figure Studio 组图]
  D --> E[报告生成]
  E --> F[repro.lock 可复现]
  F -.->|一键重跑| B
```

*从数据到交付的链路：各段由独立科研工具承接，全程留在浏览器内。*

工作台提供四种模式，对应不同的使用深度。三种脚本模式共享同一份中间表示（IR），积木、流程与代码之间可以往返互转，Python、R、JavaScript 三种语言亦可互译。

| 模式 | 面向 | 工作方式 |
| --- | --- | --- |
| 标准 Standard | 快速观察 | 数据集拖入插件即出图 |
| 流程 Flow | 管线搭建 | 38 个内置区块组成数据流图，拓扑执行、逐节点检查 |
| 积木 Block | 学习者与命令式偏好 | 类 Scratch 积木编辑器，可脚本化 |
| 代码 Code | 真实脚本 | Monaco 编辑器，Python 走 CPython（Pyodide），R 可升级到完整 webR 运行时 |

四种模式之间可以随时切换，项目数据与运行记录在切换后保持不变；一个分析的不同阶段可以在不同模式中完成——例如在流程模式整理数据、在代码模式微调脚本、再回到标准模式查看结果。图 1 的链路自左向右依次为：数据经导入或采集进入项目，画像与清洗建立分析基础，建模与推断给出结论，Figure Studio 与报告生成器完成出版交付，repro.lock 记录全程指纹并支持一键重跑。

**标准模式**是默认入口。欢迎页完成 WebGPU、OPFS 与各运行时的自检，自检结果同时决定计算档位——WebGPU 可用时各计算内核走 GPU 加速，不可用时插件以数学一致的 CPU 实现完成同样的计算；启动网格列出全部科研工具与示例项目。数据文件拖入任意插件即出图，是"有数据、想先看看"时的最快路径。

![标准模式：欢迎页与启动网格](../assets/screenshots/platform/mode-standard-welcome.png)

*标准模式：欢迎页完成环境自检，启动网格通向全部科研工具。*

插件的参数面板由宿主依据插件清单自动生成本地化表单，覆盖范围滑杆、下拉、数字、复选框、文本、文件、按钮与开关八类控件；调整参数即时重新渲染，无需编写任何代码。画布顶部的 ScienceOutputStrip 条带实时显示当前插件的关键读数——收敛判据、残差、统计量——同一套读数口径贯穿全部科研级插件。

导出分两层：画布级由统一的"导出"菜单承担，把当前插件的 2D 画布或 3D 场景下载为 PNG（3D 场景额外提供透明背景选项），或保存为工作区 `figures/` 目录下的文件；数据级由各插件在参数面板以按钮动作自声明，把所属表格数据导出为 RFC-4180 CSV。

插件画布对数据保持诚实：仿真类插件初始为空，仅在加载数据后运行，空数据启动会收到明确提示而非静默空跑；每个核心插件附带一键可载的示例数据集，加载后即可重现文档中的画面。

**流程模式**面向多步管线：区块按连线构成有向无环图，执行器按拓扑顺序增量运行——执行器带节点级增量缓存与脏值传播失效，修改单个区块的参数，只有它及其下游会重新执行；运行支持取消与并发去重，重复触发运行不会产生并行执行，取消会真正终止进行中的计算节点。每个节点可以单独查看输出与诊断信息。

![流程模式：数据流管线画布](../assets/screenshots/platform/mode-flow.png)

*流程模式：区块连线成管线，按拓扑顺序增量执行。*

38 个内置区块分八类——数据源、变换、过滤、数学、统计、单位、可视化与绘图，覆盖从"读入 CSV"到"分组聚合再画图"的常见链路。每个区块的中间结果可以展开为表格或图形预览，出错时从报错节点直接定位上游；整张管线图可保存为项目的一部分，下次打开继续编辑。

**积木模式**用 Blockly 提供命令式编程入口，积木类型覆盖循环、分支、变量、事件与绘图；积木程序与流程、代码共享同一份中间表示，可以在三种形态之间往返转换，同一逻辑不会被锁定在某一种表达里。编辑器以懒加载分包交付，不影响标准与流程模式的首屏加载。

![积木模式：Blockly 积木编辑器](../assets/screenshots/platform/mode-block.png)

*积木模式：积木程序与流程、代码共享同一中间表示。*

积木程序可以随时"升级"为可读的 JavaScript 或 Python 代码继续编辑，反向亦可把脚本"降级"回积木——转换语义由三态往返互转的单元测试固化。对教学场景，这意味着同一道练习可以先拼积木、再看代码、最后改成流程管线，三个阶段共享同一份数据与运行记录。

**代码模式**使用 Monaco 编辑器，支持 Python / R / JavaScript 三种语言：Python 运行于真实 CPython，R 在 webR 分发包存在时为完整运行时；切换语言时整份缓冲区经预览窗互译确认后应用，往返转换由单元测试固化。

![代码模式：Monaco 编辑器与语言互译](../assets/screenshots/platform/mode-code.png)

*代码模式：语言切换经预览窗确认，三语言往返互译由单元测试固化。*

Python 环境中的 `studio` 模块把项目数据直接暴露给脚本：DataFrame 可以读写项目文件，计算结果存回后自动进入实验台账与数据血缘；R 与 JavaScript 通过共享 IR 引擎访问同一份数据。`studio.plot` 经渲染桥接落到与流程模式可视化区块完全相同的插件渲染器。停止运行会终止并重启 Worker，失控循环不会卡死页面；`Ctrl+Enter` 一键运行当前缓冲区。三种语言看到的是同一个项目，区别只在表达方式。

每个项目同时是一个 **Git 仓库**（浏览器端 isomorphic-git），侧栏提供分支切换、变更审阅与规范提交；整个项目可导出为 `.clproj` 文件离线流转。数据存于 IndexedDB / OPFS，无账号，无云端副本。

分析的过程同样被完整记录：**实验台账**记下每次运行的参数、输入文件、输出指标与耗时，历史运行可按参数筛选，任意两次运行可做 A/B 对比。

![实验台账：运行历史与 A/B 对比](../assets/screenshots/platform/laboratory/runs-ledger.png)

*实验台账：运行历史按参数对比，勾选两次运行即可查看差异。*

**数据血缘**随后把文件、运行与数据依赖重建为一张分层图：一张结论可以回溯到产生它的数据文件与参数组合，数据在清洗与变换之间的每一次流动都有据可查。

![数据血缘：文件与运行构成的 DAG](../assets/screenshots/platform/laboratory/data-lineage.png)

*数据血缘：文件、运行与依赖自动重建为分层 DAG。*

## 四、端到端分析流程

以下各步对应内置科研工具，依次完成一次典型分析。每一步的输出都保存在项目内，作为后续步骤的输入；每一步也会写入运行记录，成为实验台账与数据血缘的节点。

拖入 CSV 后，**数据画像**（Profiler）给出列类型、缺失分布、相关矩阵与质量分，问题清单指出异常值与高缺失列；画像结果可以导出为 CSV，供报告与后续步骤引用。计算是流式单遍的：数值列以 Welford 递推求精确均值与方差，蓄水池采样取分位数，修正 z 分数标记离群；文本列以 HyperLogLog 估计基数；表级给出 Pearson / Spearman 相关与重复率，最终综合成 0–100 的确定性质量分。

![数据画像：列剖析与质量分](../assets/screenshots/platform/laboratory/data-profiler.png)

*数据画像：相关矩阵、质量分与问题清单。*

画像全程只读——原始数据文件在整条链路的任何步骤中都不会被修改，所有派生结果都以新文件形式写入项目。

**清洗向导**执行去重、类型修正、缺失填充与离群处理：每条规则执行前后给出行数与受影响列的摘要，每一步可回退；清洗后的数据以新文件写回项目，原始文件保持只读。

![数据清洗向导：逐步规则化清洗](../assets/screenshots/platform/laboratory/data-cleaning.png)

*清洗向导：每一步规则可回退，操作序列进入数据血缘。*

清洗规则按应用顺序保存为运行记录，同一份数据被哪些规则处理过、处理前后差异如何，都可以逐步回查。步骤模型是五类可序列化操作：类型转换、缺失值策略（删除 / 均值 / 中位数 / 零 / 前向填充）、离群标注（IQR / z 分数）、去重与列重命名；每一步永不改写输入表，因此可以逐步前进、回退、跳转或撤销单步。

需要用 SQL 直接检视数据时，**SQL 数据工作台**把项目数据文件注册进 DuckDB-WASM 虚拟文件系统并暴露为表，可直接对项目内文件运行查询；查询引擎懒加载，支持超时与中止，一次失控的查询不会拖垮整个页面。

![SQL 数据工作台：对项目数据文件运行 DuckDB 查询](../assets/screenshots/platform/laboratory/sql-workbench.png)

*SQL 数据工作台：项目文件直接暴露为 DuckDB 表，查询支持超时与中止。*

**模型工作台**拟合 OLS / logistic / ridge / 多项式回归：OLS 经 Householder QR 求解，逻辑回归用 IRLS，岭回归以 K 折交叉验证选正则参数；系数表含估计值、标准误、p 值与置信区间，2×2 残差诊断（残差-拟合、QQ、尺度-位置、残差-杠杆）同步给出。需要参数化不确定性时进入 Inference Forge 做 NUTS 推断；拟合结果作为运行记录保存，多个模型可在实验台账中横向对比。

![模型工作台：回归拟合与残差诊断](../assets/screenshots/platform/laboratory/model-lab.png)

*模型工作台：系数表、残差诊断与拟合质量读数。*

参数化不确定性由**不确定性套件与 Inference Forge** 承接：Bootstrap 置信区间、蒙特卡洛传播与 MCMC 三条路径给出 R-hat、有效样本量 ESS、HDI 与 MCSE 等收敛诊断；NUTS 采样器带 Dual Averaging 步长自适应，无须手工设定步数，另有 WAIC 与 PSIS-LOO 模型比较、后验预测检验与逐链诊断。

![贝叶斯推断：浏览器内的 NUTS 采样与后验诊断](../assets/screenshots/platform/laboratory/inferenceforge-posterior.png)

*Inference Forge：NUTS 采样与 R-hat / ESS 后验诊断，WAIC / PSIS-LOO 模型比较。*

分布拟合与常用假设检验由**快速分析工具**与统计区块承接，回归之外的单变量推断不必离开工作台。

## 五、关键技术实现

**四模式同源，三语言互译。** 积木、流程与代码三种范式共享同一份中间表示：同一程序的三种写法可以互相转换而不改变语义，Python、R、JavaScript 之间的整段代码互译经预览窗确认后应用。三语言往返互译由专门单元测试固化（`tests/editor/roundtrip-all-langs.test.ts`），语言切换链路由端到端测试覆盖。同一条管线因此可以用不同难度梯度讲解，不同背景的协作者也可以在各自熟悉的范式下工作于同一项目。

**浏览器内的运行时。** Python 运行于 Pyodide Worker 中的 CPython，可导入 `studio` 模块操作项目数据；R 配有 vendored webR 0.6.0 运行时（缺失时回退共享 IR 引擎）；DuckDB-WASM 提供 SQL 查询。全部运行时随应用自托管，离线可用。

**GPU 计算与回退。** 14 个可复用 WGSL 计算内核（全对 N-Body、D2Q9 格子 Boltzmann、波动方程 leapfrog、FFT、K-means、SpMV 等）在 WebGPU 上执行；每个内核配数学一致的 CPU 实现，单元测试对两条路径做数值一致性校验（无头 SwiftShader 实测通过限约 2e-6），涉及随机数的内核在两条路径使用同一随机数序列。数据规模低于阈值或 WebGPU 不可用时自动回退 CPU，引擎选择记入运行记录。

![引力 N 体模拟：GPU 全对内核](../assets/screenshots/plugins/nbody-3d.png)

*引力 N 体模拟：三维直接求和引力，GPU 全对内核加速、CPU 一致回退。*

**安全边界。** 插件在 Worker 沙箱中运行（isolated 模式经 OffscreenCanvas RPC 通信）；第三方 `.cspkg` 包经清单校验与 Ed25519 签名门禁加载。旧环境的 `new Function` 回退路径在界面上明确标注，不作为安全边界使用。

**隐私边界。** 应用无账号体系、无自建服务器：数据与分析记录仅存于本机 IndexedDB / OPFS；网络访问只发生在两类显式操作——用户主动配置的 Git 远程同步（经 CORS 代理）与用户主动触发的在线更新检查。除此之外不产生外发流量。

**故障隔离。** 单个插件的运行时错误由错误边界捕获，崩溃不影响宿主与其他插件，画布给出可重试的提示；运行器层面另有超时与重试机制兜底。

**本地存储分层。** 数据文件本体由 Origin Private File System 分块存储以承载大文件，项目元数据与运行记录留在 IndexedDB，历史数据由迁移逻辑平滑升级；虚拟文件系统把两层存储统一暴露给插件、脚本与 Git，版本对象与工作区文件位于同一存储栈。数据的物理位置、访问路径与版本管理因此收敛在一条路径上。

**运行时自托管。** Python、R 与 SQL 三个运行时连同静态资源一起随应用分发，不依赖公网 CDN；首次加载后全部进入本地缓存，此后离线可用。运行时版本随仓库锁定，repro.lock 的环境快照直接引用这些版本，跨设备重跑前先核对版本再执行。

**插件契约。** 每个插件由清单文件声明参数控件、示例数据与研究就绪度徽章，宿主据此自动生成本地化参数表单；插件产出的关键读数经科学输出总线进入读数条，每次运行写入实验台账。内置插件与第三方 `.cspkg` 包走同一契约与加载路径，宿主不为内置插件保留特权通道。

**测试与回归体系。** 2815 个单元测试分布在 173 个文件中，14 套端到端测试串联关键用户路径，类型检查与全部单测在 CI 中随每次提交运行；GPU 内核与 CPU 实现的一致性、三语言往返互译、报告转义与签名门禁等行为各有专项测试固化，性能基线由独立的 bench 工作流看守。引用元数据漂移、依赖漏洞等合规问题以 CI 失败的方式强制回归，不依赖人工记忆。

**性能预算与线程模型。** 构建产物受 CI 中的性能预算约束，包体积与关键路径的回归在合并前即被暴露；文件解析与计算任务位于 Worker 线程，主线程保持界面交互响应，渲染走 WebGPU 管线或 Canvas 回退。线程边界同时是安全边界——沙箱插件与宿主运行在不同的 Worker 中。

## 七、治理与路线图

项目以 MIT 协议发布，源码、173 个测试文件与 5 条 CI 工作流公开可查；发版经 Zenodo 归档并铸造 DOI，软件引用由 `CITATION.cff` 维护并在 CI 中校验；SECURITY、CONDUCT、CHANGELOG 与双语 README 齐备。第三方插件与内置插件走相同的契约与加载路径，扩展能力不依赖修改宿主。

可持续性来自几项设计：每个计算内核都有数学一致的 CPU 实现，无 WebGPU 的设备保持完整功能；数据以开放格式自由进出，项目可导出离线流转；repro.lock 的五类指纹保证历史分析在长时间后仍可判定漂移并重跑。

路线图的长期方向指向一件事：让"可复现的分析"成为科学工作的默认交付物——像网页一样易于分发，像引用一样易于核对。已交付的能力由代码与测试覆盖；未完成的事项如实列出，架构位置已经预留。

| 阶段 | 事项 | 现状锚点 |
| --- | --- | --- |
| 近期（硬化） | Git 面板差异审阅（diff 查看器）与冲突向导 | 分支、提交、克隆、远程同步已交付 |
| 近期（硬化） | 每内核 GPU 性能遥测 | 14 个内核与 GPU/CPU 一致性测试已交付 |
| 近期（硬化） | 错误处理与降级覆盖面扩展 | 错误边界与重试已就位，标记为 Partial |
| 近期（硬化） | 市场注册表与应用内安装 / 更新流 | .cspkg Ed25519 签名门禁已上线 |
| 中期（生态） | 第三方包自助提交—审核—安装管线 | 签名与沙箱基建就绪，缺自助通道 |
| 中期（生态） | gpu.* 区块族接入积木与流程模式 | Worker 端运行器与内核派发接口已预留 |

| 远期（方向） | 实时协作与项目分享（本地优先架构上的同步层） | 项目为标准 Git 仓库，天然具备交换格式 |
| 远期（方向） | 更多语言运行时经共享 IR 接入 | Python / R / JavaScript 互译机制即扩展模板 |
| 远期（方向） | 原生核心（Rust 源码）编译为 WASM 并入运行时 | 现为源码交付，运行时由 WebGPU / CPU 承担 |
| 远期（方向） | 面向教学机构的离线批量部署形态 | 单机离线能力已完整 |
| 远期（方向） | 更多期刊模板与导出格式 | IEEE / Elsevier 模板与投稿检查已交付 |

已知边界：沙箱 Worker 与宿主共享源站存储，恶意包的最终防线是签名门禁；WebGPU 不可用时进入 CPU 回退模式，功能不缺失、性能有差异。边界与缓解措施在安全文档中明文可查。

缓解是分层的：沙箱隔离运行时行为，签名门禁决定什么能进入沙箱，错误边界限制已进入沙箱的代码崩溃时的影响半径；三层各自有测试覆盖，任何一层失效都不直接暴露宿主数据。CPU 回退路径与 GPU 路径由同一套单元测试约束数值一致性，回退时的引擎选择写入运行记录，使性能差异可以事后归因。

治理的日常执行由 CI 承担：5 条工作流覆盖 2815 个单元测试、14 套端到端测试、构建与文档生成。两类测试把关键语义钉死在流水线上——GPU/CPU 一致性测试将 14 个 WGSL 内核与其 CPU 实现绑定在同一数值容差下，三态互译测试将积木、流程与代码绑定在同一中间表示上。破坏一致性或互译语义的提交会在流水线上直接失败，回归不依赖人工发现。

供应链与合规同样进入流水线：依赖清单以 CycloneDX 1.5 格式生成 SBOM，security 工作流每周重扫，高危与严重漏洞阻断合并，豁免项须写明理由并登记后续处理；引用元数据由脚本与 `package.json` 比对，漂移即 CI 失败。发版流水线把同一份构建产物归档到 Zenodo 并铸造 DOI，软件引用长期可解析。

## 八、获取与运行

- **在线使用**：GitHub Pages 在线版打开即用（见仓库 README 徽章），无需安装与注册。
- **本地开发**：`npm install` 后 `npm run dev` 启动；`npm run build:web` 纯 Web 构建；`npm run verify` 执行严格类型检查与全部单元测试；`npm run test:e2e` 串联端到端套件。
- **示例素材**：138 个示例数据集与 11 个示例工程内置可载，9 个示例程序覆盖三种语言。
- **参与贡献**：Issue 与 Pull Request 欢迎，第三方插件契约文档见仓库。
- **引用**：`CITATION.cff` 提供标准引用格式，正式发版经 Zenodo 铸造 DOI。

浏览器要求：支持 WebGPU 的浏览器（Chrome / Edge 113 及以上等）获得完整 GPU 管线；其余现代浏览器自动走 CPU 路径，功能一致、性能有差异。首次完整加载后，各运行时与数据文件均已本地缓存，之后可在离线状态下使用全部功能。

三类部署形态基于同一份纯静态构建产物，按场景选择：

| 形态 | 适用场景 | 说明 |
| --- | --- | --- |
| GitHub Pages 在线版 | 快速使用与评审 | deploy 工作流构建部署，并做站点完整性校验 |
| 本地开发 | 二次开发与插件编写 | `npm install` 后 `npm run dev` 启动热更新 |
| 自托管静态部署 | 教学机房与内网 | 构建产物为纯静态文件，HashRouter 兼容任意静态服务器 |

数据随时可以带走：项目导出为 `.clproj` 单文件，数据文件保持原始格式，Git 历史随项目一同迁移。卸载或清空浏览器数据即彻底删除全部本地副本，不存在需要申请导出的云端残留。

第一次使用不需要自己的数据：11 个示例工程覆盖不同学科的完整分析场景，138 个示例数据集经"示例数据"对话框一键载入任意插件；从示例进入、再替换为自己的文件，是多数新用户的实际路径。
