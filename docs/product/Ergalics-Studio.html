一概述与定位

科学计算的实际工作常被三类成本拖慢：

  • 环境成本。 桌面软件需要安装、配置与许可，在公共机房或借用的电脑上往往无法快速重建自己的工作环境。
  • 数据成本。 云端平台免安装，但数据要上传到服务方，涉及未发表数据或受限样本时这一步直接不可行。
  • 交付成本。 分析做完只是开始，图要排成期刊格式、结论要写进报告，数月后需要重跑时，当初的参数与数据版本未必还在。

Ergalics Studio 把分析全程放进一个网页标签页，对上述三类成本的回答构成三个基本事实：运行环境只是一个网页标签页，npm run dev 或 GitHub Pages 皆可启动；数据全程留在浏览器本地存储（IndexedDB / OPFS），无账号、无上传；每一次分析自动记录参数、种子、代码与数据指纹，复现状态可以被显式检查。

产品由四部分构成：

  1. 四模式工作台，从拖入数据查看结果，到流程管线、积木编程与真实脚本，共享同一份中间表示；
  2. 107 个内置插件，覆盖 16 个学科的可视化、仿真与数据分析；

  4. 浏览器内运行时，包括 CPython（Pyodide）、webR、DuckDB-WASM 与 14 个 WGSL 计算内核。

上述数字背后是三条已经成立的技术前提。

  1. 浏览器图形与计算接口成熟。 WebGPU 在主流浏览器默认启用，WebAssembly 以接近原生的速度运行 CPython 与 R 解释器，这使"在网页里做严肃计算"从权宜方案变为工程可行。
  2. 本地存储能力足够。 Origin Private File System 与 IndexedDB 提供 GB 级持久化，数据集、运行记录与 Git 历史都存放在其中，关闭浏览器后依然保留。
  3. 开放格式保证可迁移。 项目可随时导出为单个 .clproj 文件在设备间流转，数据文件本身不被包装进私有格式。

不同使用者在其中找到各自的入口：第一次接触数据的人从标准模式拖入文件开始看图；需要整理多步流程的分析者用流程模式搭管线并逐步预览；教编程的课堂从积木模式进入，再平滑过渡到真实脚本；熟悉 Python 或 R 的研究者直接在代码模式里调用 studio 接口操作项目数据。四种入口共享同一份数据与运行记录，起点不同，终点一致。

黑洞光线追踪

特效插件对视场内每条光线做 Schwarzschild 时空的测地线积分，光线在引力场中弯曲后采样吸积盘辐射；吸积盘的亮度与色移计入相对论性多普勒集束和引力红移，观察者倾角、盘半径与分辨率以滑块调节，渲染由 WebGPU 逐帧完成。

对时空光线做数值积分是广义相对论可视化的传统难题：光线方程没有解析解，逐帧渲染在桌面软件里意味着漫长的离线计算。

本插件把测地线积分写成 WGSL 计算着色器、交由 GPU 并行执行，使这类渲染从离线产物变为逐帧交互——引力透镜与多普勒集束不再是教科书插图，而是随滑块即时变化的第一手观察。

黑洞光线追踪
是什么
Schwarzschild 时空中逐光线的测地线积分实时渲染，吸积盘辐射计入多普勒集束与引力红移。
科研背景
2019 年事件视界望远镜发布的首张黑洞照片即由同类广义相对论射线追踪合成；引力透镜是检验强场引力理论的观测量。

实例的数值口径可以与理论直接对照：伊辛插件在周期方格子上运行 Metropolis 与 Wolff 单团簇算法，观测磁化率、比热与 Binder 累积量，χ(T) 峰位拟合给出 Onsager 临界温度；黑洞渲染对每条光线做 RK4 测地线积分，多普勒集束吸积盘、引力红移与引力透镜星空随观察者参数实时更新。峰位与理论值一旦出现系统偏离，即可作为模型或参数问题的线索回查。

统计物理

二维伊辛插件在周期边界格点上运行 Metropolis 与 Wolff 团簇翻转两种蒙特卡洛算法；温度滑块扫过临界区域时，可以观察自发磁化的形成与消失。

插件同时输出比热、磁化率与关联长度曲线，用于定位相变温度并检查有限尺寸效应，每次运行使用可复现的随机种子。

相变与临界现象是统计物理的中心问题，但除 Onsager 的二维精确解等个别情形外，临界行为只能依靠蒙特卡洛模拟获得。

本插件把这条标准研究路径完整搬到浏览器内：选择采样算法、扫描温度、读取比热与磁化率曲线的峰位、检查有限尺寸效应——教科书中的推理链条成为可亲手重演的实验。

二维伊辛模型
是什么
周期格点上的自旋相互作用模型，Metropolis 与 Wolff 团簇翻转两种蒙特卡洛算法采样。
科研背景
相变与临界现象研究的范式模型，Onsager 于 1944 年给出二维精确解；蒙特卡洛模拟由此成为统计物理的标准工具。

偏微分方程数值解

Gray-Scott 反应扩散插件以显式 FTCS 格式求解两种物质浓度的反应扩散方程，二维浓度场随时间演化出斑点、条纹与迷宫等图样；进料率与消去率两个参数决定图样类型，内置预设按 Pearson (1993) 的分类命名，也可从预设出发微调观察图样之间的转换过程。

演化在 N×N 周期网格上进行，内置质量守恒数值基准用于核对求解器。

反应扩散方程是图灵 1952 年形态发生理论的数学载体，数值求解对格式稳定性与边界处理都有严格要求，历来是计算数学教学的重点。

本插件把参数空间变成可漫游的对象：进料率与消去率扫过 Pearson 分类图，斑点、条纹与迷宫之间的转换即时呈现，图样形成的动力学从文献插图变为第一手经验。

Gray-Scott 反应扩散
是什么
两种物质浓度场的反应扩散方程数值解，图样类型由进料率与消去率两个参数决定。
科研背景
图灵于 1952 年提出反应扩散机制解释生物形态发生；斑图形成至今仍是非线性科学与发育生物学的活跃议题。

复分析可视化

域着色插件对复函数 f(z) 逐像素计算幅角与模，分别映射为色相与亮度；内置表达式解析器，支持缩放与平移，等值线带按对数模长绘制，绕数按辐角原理统计，零点与极点的位置在色彩变化中直接可读，是复变函数教学与函数探索的直观工具。

复函数没有实函数那样的函数图像，一幅图同时呈现幅角与模长是复分析可视化的长期难题，域着色以色相与亮度两个通道一并解决。

配合内置的表达式解析器与绕数统计，任意 f(z) 输入即可渲染，零点与极点的计数在图上可直接核对——辐角原理从定理变成看得见的事实。

复变函数域着色
是什么
把复函数的幅角与模长分别映射为色相与亮度的逐像素可视化。
科研背景
复分析中零点、极点与解析结构的直观研究工具，也是复变函数教学的主流图示。

流体模拟

格子 Boltzmann 插件以 D2Q9 格子模拟二维通道流，圆柱绕流的涡街随时间步推进逐步显现；计算由 GPU 内核逐步执行，并在设备不支持时降级到 CPU 完成。

直接求解 Navier-Stokes 方程在复杂边界与多相流情形下代价高昂，格子 Boltzmann 方法从介观动理学出发，以分布函数的碰撞与迁移再现宏观流体，是计算流体力学的现代分支。

D2Q9 规则的高度规整与 GPU 并行架构天然契合，卡门涡街的形成与脱落由此可以在浏览器内逐帧观察。

格子 Boltzmann 流体
是什么
以介观粒子的碰撞-流动规则模拟流体，D2Q9 格子上的二维通道流与圆柱绕流。
科研背景
格子 Boltzmann 是计算流体力学的主流方法之一，广泛用于多孔介质渗流、微流动与多相流模拟。

参数化研究

参数扫描工具对指定参数网格逐一运行模型并汇总输出指标，结果以热力图与曲线呈现，用于观察模型行为对参数的敏感性、定位稳定区间，也为后续的不确定性分析圈定输入范围。

单次模拟回答"参数取某值时会怎样"，参数化研究回答"行为如何随参数变化"——这是从演示走向研究的分水岭。

手写循环加表格汇总的传统做法把时间耗在样板代码上；本工具将网格定义、逐点执行、指标提取与热力图汇总整合为一站式流程，扫描结果随项目保存，可整组复跑。

扫描计划被展开为确定性设计点：全网格与列表轴取完整笛卡尔积，拉丁超立方轴按维度分层抽样，混合两种抽样的方案被显式拒绝——此时样本量没有无歧义的定义；执行完成后可查看响应面。

是什么
对参数网格逐一运行模型并汇总输出指标的系统性实验工具。
科研背景
敏感性分析与相图绘制的通用手段；扫描圈定的候选区间为后续不确定性量化划定输入范围。

六个实例共享同一组运行条件：全部计算发生在浏览器标签页内，不依赖任何服务器；参数与随机种子可复现，同一组输入必然得到同一组输出；关键指标经统一的科学输出总线汇入画布顶部的读数条，与图、表一起进入后续的报告与复现记录。

驱动这六个实例不需要编写代码：滑杆、下拉与文件控件即可完成全部操作；需要更细控制时切换到代码模式，同一份参数在脚本中继续可用。

流程模式

面向多步管线：区块按连线构成有向无环图，执行器按拓扑顺序增量运行——执行器带节点级增量缓存与脏值传播失效，修改单个区块的参数，只有它及其下游会重新执行；运行支持取消与并发去重，重复触发运行不会产生并行执行，取消会真正终止进行中的计算节点。每个节点可以单独查看输出与诊断信息。

适合

四端到端分析流程

每个项目同时是一个 Git 仓库（浏览器端 isomorphic-git），侧栏提供分支切换与规范提交，整个项目可导出为 .clproj 文件离线流转。数据存于 IndexedDB / OPFS，无账号，无云端副本。

数据画像（Profiler）

拖入 CSV 后，数据画像（Profiler）给出列类型、缺失分布、相关矩阵与质量分，问题清单指出异常值与高缺失列；画像结果可以导出为 CSV，供报告与后续步骤引用。

计算是流式单遍的：数值列以 Welford 递推求精确均值与方差，蓄水池采样取分位数，修正 z 分数标记离群；文本列以 HyperLogLog 估计基数；表级给出 Pearson / Spearman 相关与重复率，最终综合成 0–100 的确定性质量分。

功能

数据分析

假设检验与基础统计分析的常规入口是数据分析工具：t 检验族、单因素方差分析、Mann-Whitney U、卡方独立性检验与 Cohen's d 效应量，附 Bonferroni 与 Benjamini-Hochberg 多重比较校正；结果可直接转写为中英双语的出版级句子。

检验方法选错、效应量缺失、多重比较不校正，是应用统计中最常见的三类失误。

本工具把检验选择、效应量计算与 Bonferroni / BH 校正放进同一界面，并直接转写为出版级句子——统计规范不再依赖使用者的记忆，而被流程本身固化。

不确定性套件

"这个数字有多确定"由不确定性套件变成可计算的对象：Bootstrap 置信区间、蒙特卡洛传播与 MCMC 三条路径给出 R-hat、有效样本量 ESS、HDI 与 MCSE 等收敛诊断。

样本量足够大时自动切换 WGSL GPU 引擎，未达阈值或设备不可用时回落 CPU，两条路径在同一随机数序列下结果一致。

Inference Forge

完整的贝叶斯建模由 Inference Forge 承接：NUTS 采样器带 Dual Averaging 步长自适应，无须手工设定步数，另有 WAIC 与 PSIS-LOO 模型比较、后验预测检验与逐链诊断。

贝叶斯推断长期受制于采样调参的门槛：步长失当会导致链不收敛，结论随之失效。

NUTS 以双平均步长自适应把这道门槛大幅降低，已是 Stan 等主流平台的标准算法；本工具把同一算法带进浏览器，推断、诊断与模型比较不依赖任何本地安装。

数据血缘

台账记录的是运行，数据血缘把文件、运行与数据依赖重建为一张分层图：一张结论可以回溯到产生它的数据文件与参数组合，数据在清洗与变换之间的每一次流动都有据可查。

血缘图不是人画的，而是从文件与运行记录自动重建的，因此不依赖任何人补记，也不会过时；数据被谁处理、派生出什么，在分层图上一目了然。

这也是复现锁的漂移检查能把"哪类指纹变了"落到具体文件的前提。

五关键技术实现

四模式同源，三语言互译。 积木、流程与代码三种范式共享同一份中间表示：同一程序的三种写法可以互相转换而不改变语义，Python、R、JavaScript 之间的整段代码互译经预览窗确认后应用。

三语言往返互译由专门单元测试固化（tests/editor/roundtrip-all-langs.test.ts），语言切换链路由端到端测试覆盖。

同一条管线因此可以用不同难度梯度讲解，不同背景的协作者也可以在各自熟悉的范式下工作于同一项目。

浏览器内的运行时。 Python 运行于 Pyodide Worker 中的 CPython，可导入 studio 模块操作项目数据；R 配有 vendored webR 0.6.0 运行时（缺失时回退共享 IR 引擎）；DuckDB-WASM 提供 SQL 查询。全部运行时随应用自托管，离线可用。

GPU 计算与回退。 14 个可复用 WGSL 计算内核（全对 N-Body、D2Q9 格子 Boltzmann、波动方程 leapfrog、FFT、K-means、SpMV 等）在 WebGPU 上执行；每个内核配数学一致的 CPU 实现，单元测试对两条路径做数值一致性校验（无头 SwiftShader 实测通过限约 2e-6），涉及随机数的内核在两条路径使用同一随机数序列。

数据规模低于阈值或 WebGPU 不可用时自动回退 CPU，引擎选择记入运行记录。

安全边界。 插件在 Worker 沙箱中运行（isolated 模式经 OffscreenCanvas RPC 通信）；第三方 .cspkg 包经清单校验与 Ed25519 签名门禁加载。

旧环境的 new Function 回退路径在界面上明确标注，不作为安全边界使用。

隐私边界。 应用无账号体系、无自建服务器：数据与分析记录仅存于本机 IndexedDB / OPFS；网络访问只发生在两类显式操作——用户主动配置的 Git 远程同步（经 CORS 代理）与用户主动触发的在线更新检查。除此之外不产生外发流量。

故障隔离。 单个插件的运行时错误由错误边界捕获，崩溃不影响宿主与其他插件，画布给出可重试的提示；运行器层面另有超时与重试机制兜底。

本地存储分层。 数据文件本体由 Origin Private File System 分块存储以承载大文件，项目元数据与运行记录留在 IndexedDB，历史数据由迁移逻辑平滑升级；虚拟文件系统把两层存储统一暴露给插件、脚本与 Git，版本对象与工作区文件位于同一存储栈。数据的物理位置、访问路径与版本管理因此收敛在一条路径上。

运行时自托管。 Python、R 与 SQL 三个运行时连同静态资源一起随应用分发，不依赖公网 CDN；首次加载后全部进入本地缓存，此后离线可用。

运行时版本随仓库锁定，repro.lock 的环境快照直接引用这些版本，跨设备重跑前先核对版本再执行。

插件契约。 每个插件由清单文件声明参数控件、示例数据与研究就绪度徽章，宿主据此自动生成本地化参数表单；插件产出的关键读数经科学输出总线进入读数条，每次运行写入实验台账。

内置插件与第三方 .cspkg 包走同一契约与加载路径，宿主不为内置插件保留特权通道。

测试与回归体系。 2815 个单元测试分布在 173 个文件中，14 套端到端测试串联关键用户路径，类型检查与全部单测在 CI 中随每次提交运行；GPU 内核与 CPU 实现的一致性、三语言往返互译、报告转义与签名门禁等行为各有专项测试固化，性能基线由独立的 bench 工作流看守。

引用元数据漂移、依赖漏洞等合规问题以 CI 失败的方式强制回归，不依赖人工记忆。

性能预算与线程模型。 构建产物受 CI 中的性能预算约束，包体积与关键路径的回归在合并前即被暴露；文件解析与计算任务位于 Worker 线程，主线程保持界面交互响应，渲染走 WebGPU 管线或 Canvas 回退。

线程边界同时是安全边界——沙箱插件与宿主运行在不同的 Worker 中。

已知边界：沙箱 Worker 与宿主共享源站存储，恶意包的最终防线是签名门禁；WebGPU 不可用时进入 CPU 回退模式，功能不缺失、性能有差异。边界与缓解措施在安全文档中明文可查。

缓解是分层的：沙箱隔离运行时行为，签名门禁决定什么能进入沙箱，错误边界限制已进入沙箱的代码崩溃时的影响半径；三层各自有测试覆盖，任何一层失效都不直接暴露宿主数据。

CPU 回退路径与 GPU 路径由同一套单元测试约束数值一致性，回退时的引擎选择写入运行记录，使性能差异可以事后归因。

治理的日常执行由 CI 承担：5 条工作流覆盖 2815 个单元测试、14 套端到端测试、构建与文档生成。

两类测试把关键语义钉死在流水线上——GPU/CPU 一致性测试将 14 个 WGSL 内核与其 CPU 实现绑定在同一数值容差下，三态互译测试将积木、流程与代码绑定在同一中间表示上。

破坏一致性或互译语义的提交会在流水线上直接失败，回归不依赖人工发现。

供应链与合规同样进入流水线：依赖清单以 CycloneDX 1.5 格式生成 SBOM，security 工作流每周重扫，高危与严重漏洞阻断合并，豁免项须写明理由并登记后续处理；引用元数据由脚本与 package.json 比对，漂移即 CI 失败。

发版流水线把同一份构建产物归档到 Zenodo 并铸造 DOI，软件引用长期可解析。
