# Ergalics Studio 特效渲染专题：以物理方程为核心的 GPU 实时渲染

> **在线体验**（免安装，打开即用）：https://snowleopard-io.github.io/ErgalicsStudio/app/
> **开源仓库**（Gitee）：https://gitee.com/cnt-code/ergalics-studio
>
> 本文基于 Ergalics Studio 源码与实际运行截图写成，文中每个特效均可在在线版中调整参数并实时复现。

主流渲染方案中的"特效"通常由美术资产驱动：贴图、粒子系统与预调着色器。Ergalics Studio 的特效渲染插件组（Visual FX）采用相反的实现路径——**先有方程，后有画面**。该组共 5 个插件（黑洞 / 水波 / 天空 / 体积云 / 星空），画面均由物理模型逐像素实时计算得到；参数修改后，画面跟随物理规律而非动画曲线变化。

这也是该组被归入插件库 16 个学科分组、而非单纯装饰性功能的原因。以下拆解其中四个。

## 黑洞 · 3D 光线追踪（fx.blackhole）

该插件是本组中技术密度最高的一个，其光线追踪实现值得单独展开。

**光线生成。** 画面为一张全屏四边形，片元着色器中每个像素通过逆投影矩阵（`uProjInv`）与相机世界矩阵重建世界空间光线（起点与单位方向），这是光线追踪的标准入口；其后的每一步均由物理方程驱动。

**测地线积分。** 史瓦西时空的零测地线在 Binet 形式下化为二阶常微分方程 u″ = −u + 1.5u²（u = 1/r，以史瓦西半径 r_s = 1 为单位）。每条光线在其轨道平面内以四阶龙格-库塔法（RK4）数值积分，步长自适应：靠近黑洞（u 较大）时步长收窄，远处放宽，步数预算上限 640。终止条件仅两种：u ≥ 1 对应光线落入事件视界（该像素保持纯黑），r > 3000 r_s 对应光线逃逸。

**结构的涌现。** 黑洞影像中的标志性结构均非显式绘制，而是积分过程的自然结果：

- **吸积盘**并非几何体贴图。每条光线穿越盘平面（y = 0）时记录交点并累计发光；盘内缘默认取最内稳定圆轨道 ISCO（3 r_s），该边界由广义相对论自身给出；温度剖面遵循 Shakura–Sunyaev 薄盘模型 T ∝ r^(−3/4)，颜色由普朗克黑体辐射定律计算。
- **多普勒集束与引力红移**：盘物质以开普勒速度做圆轨道运动，总频移因子 g = g_grav · g_doppler，观测强度按相对论不变量 I_obs = g⁴·I_em 缩放，因此吸积盘呈现真实的不对称亮度分布。
- **光子环、爱因斯坦环及盘的多重像**（光线绕黑洞半周后自盘面背侧再次穿越到达相机）均由测地线积分涌现；积分逐步检测盘面穿越（相邻步 y 坐标变号即线性插值求交点），并带透射率累计，半透明层次与多重像由此获得正确处理。

由于 Binet 形式将三维光线追踪问题约化为轨道平面内的二维常微分方程，该逐像素光线追踪可在浏览器中达到交互帧率，无需专用硬件。调整质量、盘峰值温度与观测距离，光子环半径随 Schwarzschild 半径相应变化，可作为广义相对论教学的定量演示。

其插件元数据注明：阴影角直径可与事件视界望远镜（EHT）观测结果对比。定级"准研究级"，并标注边界——不含 Kerr 自旋与 GRMHD 流体模型。

## 水波 · 3D 流体（fx.water）

单个插件包含两种真实计算模式：

- **涟漪模式**：波动方程的 GPU FDTD 求解器。支持点击滴落、降雨、双源干涉，含吸收边界与池底焦散；波速满足浅水关系 c = √(gh)，并强制 CFL 稳定性条件。适用于波动干涉的课堂教学演示。
- **海面模式**：Gerstner 波列叠加，锚定精确深水色散关系 ω² = g·k，海况按 Pierson–Moskowitz 谱标度，白沫由雅可比行列式判定——该模型为影视与游戏行业的标准海洋运动学模型。

![水波：FDTD 涟漪与 Gerstner 海面](https://gitee.com/cnt-code/ergalics-studio/raw/main/docs/assets/screenshots/plugins/fx-water.png)

元数据中明确标注海面为运动学模型而非 Navier–Stokes 求解。将局限写入元数据的做法，与实际计算能力的边界保持一致。

## 星空 · 夜天渲染器（fx.stars）

该插件的天文学约束最为严格，主要构成如下：

- 银河带锚定 J2000 银极（RA 192.86°, Dec +27.13°）与银心（RA 266.41°, Dec −29.01°），经 Meeus 历表公式换算至地平坐标系；
- 恒星周日运动由 GMST（格林尼治平恒星时）驱动，时间推进时天穹整体旋转；
- 光污染按 Bortle (2001) 分级表建模，天顶亮度与极限星等对应参考表；全天可见星数遵循经验计数 N(m) ≈ 9096·e^((m−6.5)/1.35)；
- 流星为泊松过程（指数间隔、种子确定性流），月光冲淡与视宁度闪烁设为独立参数。

![星空：Bortle 光污染与银河](https://gitee.com/cnt-code/ergalics-studio/raw/main/docs/assets/screenshots/plugins/fx-stars.png)

将 Bortle 等级从 1 调至 9，可完整观察银河从清晰可见到被光污染淹没的过程，可作为光污染教育的定量演示工具。

## 日光天空 · 大气散射（fx.sky）

Nishita 型解析式单次散射大气：Rayleigh 与 Mie 散射、浑浊度参数、逐样本光照步进；行星/大气壳层取 6360/6420 km，指数标高 8 km / 1.2 km，瑞利散射系数 β_R = (5.8, 13.5, 33.1)×10⁻⁶ /m。日出日落色彩来自穿过地影的物理晨昏蒙影，太阳盘面含临边昏暗，月球按真实月相明暗；太阳方位由 Meeus 低精度历表驱动（精度约 ±1 角分）。

天空颜色（瑞利散射的波长依赖性）与晚霞（低太阳高度角下的长路径消光）在教科书中通常只给出定性结论，该插件提供的是可调参数的散射积分器。

## 共同的工程底座：可复用的光追积木

支撑该组插件的并非五个孤立着色器，而是一个**共享光追核心**（`src/core/raytrace/`）。该核心将全屏光追渲染的通用环节拆分为标准 GLSL 代码块：相机光线重建（`RT_CAMERA_RAY`）、哈希/值噪声/fbm 工具集（`RT_NOISE`）、普朗克黑体配色（`RT_BLACKBODY`）、程序化星场（`RT_STARS`）、大气散射底座（`RT_SCATTER`）、色调映射（`RT_TONEMAP`），各插件按依赖顺序拼接进各自的片元着色器。黑洞的测地线积分、天空的 Rayleigh/Mie 积分为插件专属代码，相机、噪声、黑体、调色等环节则全网复用，显著降低了新增光追特效插件的边际成本。这与项目配套的 14 个 WGSL 计算内核（WebGPU 通用计算）遵循同一工程原则：GPU 代码按内核组织、可测试、可复用。

宿主机制方面，五个插件均通过工作台统一的 `renderToScene` 契约挂载至 Three.js 3D 场景（按需懒创建、插件间干净清理），画面为全屏着色器实时渲染；场景参数可保存为 JSON 预设文件；全部接入插件库统一的科研元数据系统——就绪分级、物理量单位、可复现标记，与统计、物理类插件采用同一标准。特效渲染组因此不是孤立的装饰模块，而是插件体系的一等公民。

## 诚实的边界

该组插件的"局限"全部记录于源码的元数据注释中，任何人查阅 manifest 即可获得：黑洞不含自旋与磁流体模型、海面非 Navier–Stokes 求解、星空为程序化星点而非真实星表、天空未含多次散射与臭氧吸收。这些标注本身即项目对"科研就绪分级"承诺的组成部分——演示级即为演示级，准研究级会明确说明其精确范围。

## 结语

这组插件的价值不在于渲染效果本身，而在于其确定性：**每个像素的变化均可追溯至某个物理量的变化**——质量、波速、浑浊度、Bortle 等级、恒星时。"特效"由此还原为教学与研究工具，"美观"成为物理正确性的副产品。
