一宿主与插件的契约

1.1Plugin 接口与 PluginApi 能力面

每个插件实现统一的 Plugin 接口，宿主在正确的时机调用对应方法，插件不感知界面细节：

方法作用
init 与 destroy初始化与销毁，宿主负责 GPU 安全的资源回收
activate 与 deactivate激活与去激活，驱动 2D/3D 视口切换与残留帧清理
render 与 updateParams绘制与参数更新（右侧面板响应式表单）
getParams 与 compute参数读取与计算
loadData接收宿主分发的数据（文件路由与渲染桥接的入口）
renderToScene可选能力声明，激活时获得宿主 Three.js 场景句柄

宿主向插件提供 PluginApi 句柄，能力面如下：

能力组内容
本地化插件文案按当前语言取值，语言切换时参数面板自动重建
状态上报插件向状态栏上报运行状态与进度
性能上报帧时间与真实 GPU 时间进入性能监控与告警
通知按严重级别的横幅与提示
文件访问项目数据文件解析（项目自有文件、内置示例与代码模式文件共享同一套逻辑）
参数读写项目级参数的持久化存取
GPU 计算面createBuffer、write、read、compileKernel、compilationInfo 与一次性 run（详见 05 篇）

1.2声明式参数面板

插件在清单中声明参数表，宿主据此自动生成本地化的响应式参数面板，支持八类控件。插件作者不需要写任何面板代码——声明"我要一个范围滑杆，步长多少、默认多少"，右侧面板就会出现对应的表单项，并在语言切换时自动重建。

控件用途示例
范围（滑杆）引力常数、阻尼系数
下拉场景预设、投影方式、调色板
数字分箱数、步长
复选框轨迹线、网格显示
文本列名、标签
文件附加数据选择
按钮重新播种、导出
开关运行/暂停之外的布尔状态

1.3插件生命周期

插件生命周期由插件运行时统一编排，从注册到销毁共六个阶段：

图 1　插件生命周期：注册、加载、激活、渲染循环、去激活、销毁

去激活与销毁是两个不同的阶段：切换插件时旧插件只去激活，资源保留以便快速切回；只有项目关闭或插件卸载时才真正销毁。GPU 资源（缓冲区、管线）的回收由宿主统一执行，插件无需也无力处理 WebGL 或 WebGPU 对象的释放细节。

三市场目录与两级加载

市场目录（src/plugins/marketplace.ts）把每个内置插件以精选标签、流行度与分类筛选（科学、趣味、工具）的形式呈现，社区"敬请期待"条目以占位符列出。加载策略分两级：

图 5　两级加载策略：核心自动加载，趣味手动加载

自动加载失败可重试：插件运行时把"初始化完成"作为状态机节点，失败后注册表不会进入就绪态，用户重试不会被误判为重复加载。

四第三方包（.cspkg）与沙箱

.cspkg 包是包含 manifest.json、入口模块与资源的 ZIP 压缩包（fflate 打包）。加载时校验清单：必填字段、插件 id 格式、入口路径穿越防护与沙箱枚举。清单声明 sandbox 字段，共有两级：

  • isolated（默认）：入口代码运行在 Web Worker 内，拥有独立全局作用域，无法访问宿主页面的全局变量、DOM 与状态库；画布渲染通过转移的 OffscreenCanvas 完成，宿主与 Worker 之间只走类型化 RPC 协议（src/core/sandbox.ts 与 src/core/plugin-worker.ts）。
  • trusted：在宿主上下文中执行，拥有完整 DOM 访问权，仅建议用于自研包。
图 6　第三方插件的加载与通信流程

已知限制（如实记录）：Worker 与页面共享同源的 IndexedDB；当 Worker 不可用时的遗留回退方案（new Function 加遮蔽全局变量）只是尽力而为的近似，并非安全边界，回退启用时界面会明确告警。包签名与第三方安装管线是市场方向的下一个里程碑。

五文件路由

用户把任意文件拖入中央视口或插件列表时，宿主按魔数与扩展名（可选 WASM 辅助检测）识别格式并路由到匹配插件：

图 7　文件路由：魔数识别、科研调度与插件匹配

路由的末端是"示例对话框"：每个核心插件都附带示例数据集，在"示例"对话框中一键加载即可看到真实可视化；示例资产经 exampleAssets 与 examples 模块统一发现与加载。用户不需要先去找数据再学插件——先看效果、再换自己的数据，是产品设计上刻意保留的顺序。

科研二进制格式的解析细节（HDF5、NetCDF、FITS、Zarr、Parquet）在第六篇"科学计算子系统"中展开； GPU 计算面（createBuffer、compileKernel 等）在第五篇"GPU 计算与原生核心"中展开。
